# Honor — диагностическая P0.5 / 0.1.5-p0 / code 6

Обновить поверх прежней облачной версии без удаления/очистки/переимпорта. Code 6 на Honor **NOT_RUN**; позиция и Дмитрий пока не объявлены исправленными. Подробности в [отчёте](P0_5_RESOURCE_STATE_REPORT.md).

1. «Диагностика TTS» → «Проверки» → «Начать новую трассу чтения», закрыть диалоги. Пометка x1 → поворот → пометка x2 другого раздела → поворот. Если вернулось x1 — сразу открыть диагностику и «Копировать»: достаточно одной трассы, больше повторять по кругу не нужно. Если всё верно, отдельно проверить несколько секунд ожидания перед поворотом и перезапуск после x2.
2. В landscape свайпами перейти в соседние разделы и обратно: ширина полная с полями 16 CSS px. Проверить также переход к пометке другого раздела.
3. Один раз: «Диагностика TTS» → «Проверки» → «Сравнить маршруты: 4 сетевых запроса». Прочитать назначение и нажать «Запустить». Четыре последовательные проверки обоих голосов/двух маршрутов без кеша и повторов. Обычный маршрут не меняется. Дождаться результата, снова открыть диагностику и «Копировать». При уходе Home проверка отменяется, сама не возобновится.
4. Проверить размер шрифта, сохранённые пометки, обычную Светлану с подсветкой/прокруткой, Пауза/Home/блокировку и ручное продолжение.

Кнопка «Копировать» выдаёт общий JSON: reader — последняя числовая трасса, tts — последняя сессия, для сравнения purpose=routeComparison. В tts четыре строки current/readest × Дмитрий/Светлана, maxAttempts=1; config/SSML accepted и HTTP101 не равны синтезу. Отмечать audioBytes/frames, synthesis, playback, responseStatus и code. Полных текстов книг, путей, токенов и payload в экспорте нет.

В ответе указать code 6, номер пункта, PASS/FAIL и общий JSON. Не нужны десятки запусков, ADB или очистка данных. P1 не начинается автоматически.
