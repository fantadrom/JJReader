# JJReader — техническое задание для Codex

Редакция: 27.10.2026, P1.1 после ручной проверки P1/code11; P0.8 принят и слит в master. Платформа: Android. Язык интерфейса: русский.

Документ содержит общие требования и последовательные задания P0–P5. Это не поручение реализовать все этапы за один запуск. P0 принят пользователем; текущий запуск — только исправление P1.1. Для последующих этапов требуется отдельное поручение. Каждый следующий этап запускается отдельным заданием. Общие требования обязательны для соответствующего этапа; функции будущих этапов не реализовывать заранее.

Источник концепции: https://docs.google.com/document/d/1ZLhnG59ZPnO4KHCvJHVi3pAjZCCxJenFB4r9N4reCAQ/edit
Этот документ учитывает последующие согласования в обсуждении. При расхождении приоритет имеют требования ниже. Не менять исходный Google Doc.

## 1. Цель

Простая читалка EPUB для авторской вычитки. Пользователь читает роман, выделяет места, добавляет короткие комментарии или цветовые пометки, затем экспортирует замечания с контекстом и исправляет оригинал на компьютере. Редактирование текста книги в JJReader не требуется.

Ключевые свойства: минимум действий при комментировании; сохранность результатов; точная привязка к выделенному месту; удобный экспорт; сетевая озвучка Edge TTS.

Не реализовывать: другие форматы книг, редактирование EPUB, перенос пометок между редакциями, статусы исправлений, облачную синхронизацию, собственный сервер, аккаунты, платные TTS, фоновую озвучку, управление из уведомления или гарнитуры, сложную библиотечную каталогизацию. Специальный интерфейс сносок (например, всплывающие карточки) не входит в первую версию. Уже работающие обычные ссылки, переходы к сноске и возврат сохраняются.

Windows-команды предоставлять для PowerShell (`.\gradlew.bat ...`), не требовать Unix-команд на компьютере пользователя.
- Название JJReader; предлагаемое applicationId/namespace `com.fantadrom.jjreader`; minSdk 31. Kotlin, предпочтительно Jetpack Compose для оболочки; допускается встраивание Views/Fragment/WebView, необходимых движку чтения. Не переписывать стабильный движок ради полностью Compose-интерфейса.
- Репозиторий уже создан: https://github.com/fantadrom/JJReader.git . Основа текущего P1 — master с принятым P0.8 (merge 67acede); сохранять существующий движок и пользовательские данные, не создавать проект заново. В начале проверить ветку, AGENTS.md, структуру и доступную среду. Не работать в репозиториях JJMedia/JJTimer/CopperScroll. Если JJReader недоступен — сообщить об этом; не создавать другой удалённый репозиторий.
- Выбрать совместимые стабильные AGP/Gradle/JDK/Kotlin/compileSdk/targetSdk по актуальным официальным требованиям и доступной среде; зафиксировать версии. Не использовать динамические `+`, не обновлять стек между этапами без причины.

## 3. Внутренняя книжная полка

1. Пользователь выбирает стартовую папку через SAF; приложение сохраняет разрешение, если провайдер допускает persistable URI permissions. Общий доступ ко всему накопителю не нужен.
2. Из папки выбираются EPUB для импорта. Во внутреннее хранилище приложения сохраняется самостоятельная копия. Пометки и позиции привязаны к внутреннему ID книги, не к имени файла или исходному URI.
3. EPUB не изменяется при добавлении пометок. Пометки, текстовая модель, позиции и настройки хранятся отдельно от копии EPUB. База/файлы должны переживать перезапуск, смерть процесса и обновление приложения с сохранением данных.
4. Полка показывает минимум: название, имя исходного файла или дату импорта для различения редакций, прогресс и количество пометок. Достаточно простого списка.
5. При запуске открывать последнюю книгу и её позицию; если её копия недоступна — полку с понятным сообщением. Если книг нет — выбор/просмотр стартовой папки. Потеря доступа к исходной папке не мешает читать импортированные книги.
6. Обычное переключение книг не вызывает предложения выгрузить или удалить пометки: каждая книга сохраняет свои данные.
7. Удаление книги с полки с подтверждением удаляет её внутреннюю копию и связанные пометки, черновики, текстовый индекс, позиции и аудиокеш. Исходный файл в стартовой папке не удаляется.
8. Отдельная команда с подтверждением удаляет только пометки выбранной книги. Она не удаляет книгу и позицию чтения. Отмена диалога не меняет данные.
9. Повторный импорт идентичного по SHA-256 исходных байтов EPUB открывает существующую копию; несколько совпадений требуют явного выбора. Обязательной команды «импортировать отдельно» нет; прежние дубли остаются доступными с прежними ID и пометками. Разные файлы с одинаковыми именами/заголовками не объединять. Новая редакция EPUB — отдельная книга без переноса пометок.
10. Импорт должен быть атомарным: при ошибке/нехватке места не оставлять видимую сломанную книгу и не повреждать существующие данные. Повреждённые, защищённые DRM или неподдерживаемые EPUB отклонять понятным сообщением.

## 4. Чтение и управление

### 4.1. Отображение

- EPUB с изменяемой раскладкой (reflowable) — обязательный сценарий. EPUB с фиксированной раскладкой не входит в обязательную поддержку первой версии: не отображать его молча неправильно.
- Основной режим — отдельные исходные ресурсы стабильного Readium: вертикальная прокрутка, пустой хвост до последней строки у верха viewport и переход следующим намеренным жестом на краю; обратно — к концу предыдущего ресурса. Достижение края/инерция сами не переключают ресурс. Единая лента не обязательна, остаётся диагностическим сравнением без развития преобразователя.
- Явный вход в начало ресурса сохраняет естественный небольшой отступ текущей раскладки (устойчивый scrollY=0). Произвольные якоря пометок/TTS/позиции восстанавливаются по прежним правилам без нового фиксированного отступа. Для входа в начало/заключительный экран сохраняется необязательный версионированный семантический признак; пиксельная координата не хранится, после ручного перемещения снова сохраняется обычный якорь.
- Смена шрифта и размера текста; разумный небольшой набор встроенных шрифтов с кириллицей. Импорт пользовательских шрифтов не обязателен. Изменение настроек сохраняет место по тексту, не по пиксельному смещению.
- Дневная и ночная темы; авторежим следует системной теме. Яркость изменяется только для окна JJReader. Настройки сохраняются.
- Поддерживать обе ориентации, безопасные отступы от системных панелей и клавиатуры. Поворот не теряет чтение/выделенную пометку/черновик.
- Во время активного чтения удерживать экран включённым; после ухода из приложения не удерживать устройство бодрствующим.

### 4.2. Выделение и жесты

Выделение внутри исходного ресурса поддерживается. Создание пометки через его границу не требуется. Приоритет: выделение и элементы управления/ссылки/пометки → яркость в левой полосе → прокрутка и краевой переход. Один жест выполняет одно действие; движение яркости не прокручивает текст и не переключает ресурс.

- Вертикальное движение в области текста, кроме левой полосы шириной 10% области чтения, прокручивает текст.
- Вертикальное движение, начатое в левой полосе, меняет яркость после превышения порога движения. Долгое нажатие в этой полосе всё ещё может начать выделение. При уже начатом выделении маркеры выделения имеют приоритет над яркостью.
- Короткое касание левой/правой трети внутри ресурса перемещает назад/вперёд примерно на высоту области чтения с перекрытием одной строки.
- Правое касание сразу открывает начало следующего ресурса, если последний значимый элемент/последняя строка целиком видны и ниже свободна хотя бы одна обычная строка; уже пройденный текст в хвосте не нужно возвращать в экран. Частичная строка или недостаточный запас требуют обычного шага. Завершающие иллюстрация/таблица/подпись не пропускаются.
- Левое касание при показанном начале содержимого сразу открывает заключительный экран предыдущего ресурса: запас снизу min(4*lineHeight, viewportHeight/2), выше — предшествующий текст. Не требовать технического scrollY=0 ради верхних полей. Обложка перед заголовком считается началом; частично обрезанное содержимое не считается показанным началом. Короткий ресурс не прокручивать за начало ради точного запаса.
- Обратный вертикальный жест сохраняет прежнее размещение конца около верха; TAP и GESTURE используют разные явные размещения. Физический хвост P0.8 не уменьшать. На первой/последней границе переход безопасно отсутствует; пустые/image-only ресурсы доступны без автоматического пропуска.
- Метрики содержательных границ кешировать, инвалидировать после изменения ресурса/шрифта/viewport/панелей/загрузки медиа/значимой раскладки. Не обходить DOM/текст на каждом касании, scroll и40ms poll; revision, документ, цитата и ACK остаются обязательными.
- Касание центральной трети показывает/скрывает верхнюю панель с меню и нижнюю панель с горизонтальным ползунком всей книги.
- Ползунок отражает весь читаемый текст. Касание дорожки переходит к выбранному месту; перетаскивание позволяет быстро перемещаться по книге. Обновления ограничивать по частоте и применять последнее положение, не ставить в очередь множество загрузок.
- Меню предоставляет полку/открытие книги, оглавление, список пометок, настройки и текущую пробную озвучку; экспорт добавляется в P3.
- Долгое нажатие начинает выделение. Команды: копировать, добавить/редактировать комментарий, выбрать цвет. Выделение можно расширять через строки и за пределы текущего экрана; создание межресурсной пометки не требуется. Цветовые/полноценные операции относятся к P2; P1 сохраняет действующие пометки и комментарии.
- При активном выделении жесты редактирования диапазона имеют приоритет над перелистыванием и яркостью. Нажатие на пометку имеет приоритет над зонами перелистывания.
- После переходов через оглавление, ползунок или список пометок доступна команда возврата к предыдущему месту. Не требуется полная история всех прокруток.

### 4.3. Процент вместо страниц

- Номера страниц не реализовывать.
- Пустой хвост не добавляет символы и не влияет на процент. Ресурсы без текста сохраняют отдельное визуальное положение средствами движка, без фиктивного текстового якоря.
- Процент = позиция последнего видимого символа в читаемом тексте книги / общее количество символов читаемого текста × 100.
- Единую текстовую модель строить в порядке чтения EPUB; не считать HTML/CSS/служебную разметку и не добавлять оглавление второй раз. Текст иллюстраций/alt не должен неожиданно менять прогресс.
- Зафиксировать правила Unicode, пробелов и разделителей абзацев. Для счётчика допустимы Unicode code points; не разрезать суррогатные пары и пользовательские символы при обрезке/якорях.
- Показывать целые проценты; до достижения конца не округлять до 100. На последнем читаемом символе — ровно 100%. Пустая книга обрабатывается без деления на ноль.
- Прогресс пересчитывается после изменения видимой области/шрифта/ориентации, но сама позиция остаётся привязанной к тексту.

## 5. Пометки и сохранность

1. Пометка содержит ID книги, устойчивый диапазон текста, цитату, необязательный текст комментария и необязательный цвет. Хотя бы текст или цвет должны присутствовать; случайный пустой черновик не создаёт пустую пометку.
2. Должна быть возможность цветового выделения без ввода текста. Палитра небольшой фиксированной ширины: красный, синий, зелёный, жёлтый, фиолетовый; цвет подписан для доступности. Значения цветов не привязывать к типам ошибок в первой версии.
3. К цветному выделению можно добавить текст; у пометки с текстом можно менять/снимать цвет, сохраняя комментарий.
4. В тексте показывать цвет выделения и значок комментария для пометки с текстом. Значок привязан к диапазону и не перекрывает буквы, не меняет раскладку строк. Предпочтительно поле возле текста; точное решение подтвердить в P0. При необходимости отступить от буквального «над словом» ради читаемости, описав решение.
5. Нажатие на пометку/значок открывает просмотр, редактирование и удаление. При нескольких пересекающихся пометках — выбор нужной из списка.
6. Пересекающиеся диапазоны сохранять независимо; одинаковое слово в разных местах не смешивать. При неоднозначном цвете пересечения не уничтожать данные: выбрать детерминированное отображение, а в просмотре показать все пометки.
7. При создании комментария сразу показывать цитату, установить курсор в поле и открыть клавиатуру. Сохранение должно требовать одного явного действия. После него восстанавливать место чтения.
8. Черновик комментария автосохраняется и восстанавливается после прерывания; не считать задержку фонового debounce достаточной гарантией. Отдельные сохранённые пометки записывать надёжно сразу после действия пользователя.
9. Удаление одной пометки — с короткой возможностью отмены; удаление всех — с подтверждением. Реализовать поведение без сложной многошаговой истории undo.
10. Локатор хранить вместе с цитатой/контекстом и проверкой соответствия тексту. Использовать возможности движка, а не только поиск цитаты или номер абзаца. Не привязываться к экранным координатам. После перезапуска, смены шрифта и поворота возвращаться к тому же месту.
11. Хранить извлечённый текст книги и доступные данные контекста так, чтобы повреждение/потеря копии EPUB не уничтожили возможность экспортировать сохранённые замечания. Удаление книги пользователем, напротив, очищает связанные данные по п. 3.
12. Экспорт/копирование ничего не удаляют и не помечают исправленным.

## 6. Список, контекст и объединение

### 6.1. Список

Показывать все пометки открытой книги в порядке расположения, не создания. При равном начале — устойчивый дополнительный порядок. Есть глава, цитата/контекст, цвет и комментарий. Нажатие переходит к месту; доступно возвращение к списку. Включать цветовые выделения без текста.

### 6.2. Контекст

- Настройка N символов с каждой стороны, по умолчанию N=350. Одно значение для текущей книги, сохраняется. Изменение применяется ко всем пометкам без их пересоздания.
- Сам выделенный диапазон сохраняется полностью и не входит в лимит N.
- Слева в пределах N выбрать самое дальнее начало абзаца: таким образом контекст может включать несколько коротких абзацев. Не обрезать обязательно по ближайшему абзацу.
- Справа в пределах N выбрать самое дальнее окончание абзаца.
- Если границы абзаца в диапазоне нет — обрезать по границе целого слова внутри лимита. Не разрезать Unicode-символ. На обрезанной стороне добавить многоточие; у настоящего начала/конца текста не добавлять его.
- Граница ресурса отображения не равна логической главе. Один XHTML может содержать несколько глав; одна глава может занимать несколько ресурсов. В P2 контекст и объединение ограничиваются логическими главами по TOC, ресурс — только запасная граница при неоднозначности.
- Контекст не переходит границу главы; если оглавление не даёт однозначных границ, использовать заранее определённые разделы по spine/resource и не выдумывать главы по номерам файлов. Реальное название главы брать из EPUB, без предположения о «Глава N».
- Пример согласованного смысла: к «Старшой» в предложении «— Что же, — растерянно сказал Старшой…» контекст может начинаться несколькими абзацами ранее с «— Лукреция, дорогая…», если это укладывается в N. Текст примера из концепции — тестовая иллюстрация алгоритма, не материал для литературного анализа.

### 6.3. Объединение в отчёте

- Исходные пометки остаются отдельными. Объединение — представление в списке контекстов/экспорте, а не изменение записей.
- Если выделенный диапазон другой пометки попадает в контекст группы, включить её в группу. Границы контекста группы считать от самого раннего начала и самого позднего конца выделений с тем же N по сторонам.
- Повторять включение до устойчивого результата. Допускается длинная цепочка; через границы глав не объединять.
- Простого пересечения двух пустых участков контекста недостаточно, если сами выделения не попали в контекст другой группы. Формализовать алгоритм детерминированно; тестировать, что порядок создания/обхода не меняет итог.
- Каждую пометку экспортировать ровно один раз. Несколько комментариев к одному диапазону и пересечения не терять.
- Внутри группы нумеровать пометки; номера возле диапазонов связать с подписанными комментариями после контекста. Повторяющиеся цитаты различать по положению и номеру.

## 7. Экспорт

### 7.1. Буфер обмена

- Одним действием скопировать все пометки текущей книги с контекстом и заголовками глав. Если пометок нет — понятное состояние без ошибки.
- Формат — обычный текст с буквальными маркерами: выделенные фрагменты обрамлены обратными кавычками; комментарий — двойными звёздочками. Для цвета без текста подпись, например `**красный**`.
- Пример одиночной записи:

```text
Глава 1
Раннее `утро`[1] застало нас в дороге.
[1] **заря**
```

- Если пометка содержит цвет и текст, передать оба, например `[1] **красный; заря**`. У нескольких пометок подписи отдельные.
- При пересечении диапазонов/одинаковых слов маркеры и подписи должны оставаться однозначными. Для сложного пересечения допустим общий помеченный участок и отдельные подписи с номером и точной цитатой. Не пытаться представить пересечения некорректной вложенностью маркеров.
- Определить экранирование исходных обратных кавычек/звёздочек и переносов строк комментария. Не терять исходные символы.
- Обрабатывать ошибку/слишком большой объём копирования без падения; предлагать DOCX, не обрезать молча.

### 7.2. DOCX

- Создавать локально на Android, без сервера, облачной конвертации или зависимости от установленного Word. Выбор места сохранения через SAF; возможность системной отправки готового файла.
- Сохранять абзацы и пользовательские цветовые пометки. Остальное оформление EPUB (шрифты, курсив, жирное, стили, таблицы, сложная вёрстка) не требуется. Для исходных таблиц достаточно читаемого текста с разделителями; не обещать восстановление таблиц. Не включать нетекстовые элементы как обязательные объекты отчёта.
- Использовать единый читаемый шрифт/размер, заголовок книги, реальные названия глав, контекст, номера пометок и отдельные блоки комментариев. Комментарии не оформлять как рецензионные примечания Word.
- Текстовые пометки без цвета обозначать номером/подчёркиванием; не требовать от читателя угадывать, к какому месту относится комментарий.
- Для пересекающихся разных цветов допустимо детерминированное отображение одного цвета на общей части, но подписи должны содержать точные цитаты и все исходные цвета. Не менять смысл/терять цвет в данных.
- Генерация асинхронная; при отмене или ошибке не сообщать об успешном сохранении. Сохранять итог целиком, не повреждать пометки.
- Подготовить пример отчёта с русским текстом, объединённой группой и пересечениями; проверить открытие в Word/LibreOffice при наличии и структуру OOXML. Для визуальной проверки можно дополнительно скопировать сгенерированный на Android DOCX в среду разработки. Сам экспорт на устройстве должен работать без этих инструментов.

## 8. Edge TTS

### 8.1. Обязательный объём

- Основной и единственный обязательный провайдер первой версии — сетевой Edge TTS, голоса `ru-RU-DmitryNeural` и `ru-RU-SvetlanaNeural`. Проверить фактическую доступность голосов на P0; не обещать результат по одному наличию имени в списке.
- Прямое подключение приложения к сервису, без собственного промежуточного сервера, аккаунта Azure, встроенных чужих ключей и платного API. Не копировать секреты из других приложений. Если текущий сервис недоступен — честно сообщить, не подменять его платным сервисом или локальным голосом.
- Отправляется только текст для выбранной озвучки и небольшой буфер следующих фраз, не вся библиотека, не комментарии. Перед первым включением кратко пояснить, что текст отправляется Microsoft и нужен интернет. Это часть поведения приложения, не отдельная регистрация.
- Синтезировать блоками по 1–2 предложения; размер сетевого блока не обязан совпадать с размером навигационной фразы. Ограниченный prefetch, без генерации всей книги.
- Корректно разделять русский текст: инициалы, сокращения, многоточия и диалоги. Не разбивать строку по каждому символу точки. Не пропускать слова и не озвучивать служебную разметку/номера наших пометок.
- Небольшой ограниченный кеш аудио: ключ включает текст, голос и влияющие настройки синтеза; повтор фразы использует готовое аудио. Отдельные хеши/поколения запросов исключают воспроизведение старой книги/голоса после переключения.
- Пауза/продолжение, предыдущая/следующая фраза, старт с выбранного места, выбор голоса. Желательна настройка скорости: подтвердить способ в P0/P4, не менять голос непредсказуемо при её изменении.
- Подсветка текущей фразы; пословная подсветка не обязательна. Автопрокрутка по аудиопозиции, а не по приблизительному таймеру. Пользовательское выделение и подсветка озвучки различимы.
- Пауза сохраняет очередь для ручного продолжения. Ручной переход по пометке/TOC/ползунку/ссылке/кнопке/краю сбрасывает её. Автоматический TTS-переход между ресурсами сохраняет актуальную очередь. В P1 остаётся рабочая проба из пяти фраз; полный плеер — P4.
- При начале выделения/открытии комментария — пауза; после сохранения продолжение только вручную.
- При уходе приложения в фон, выключении экрана или потере аудиофокуса — пауза. Возврат сам звук не включает. Не запускать фоновый сервис, уведомление воспроизведения, alarm или постоянный WakeLock.
- Положение озвучки сохраняется отдельно от просмотра; после возвращения можно продолжить с приостановленной фразы. После смерти процесса допустимо начать фразу заново, не обещать возобновление с точного аудиосэмпла.
- Обработать отсутствие сети, timeout, отказ сервиса, пустое/повреждённое аудио. Ограниченные повторы, отменяемые запросы, понятная ошибка. Нет бесконечного автоперезапуска и автоматической смены провайдера.
- Чтение, пометки и экспорт работают без интернета и при полной недоступности TTS.

### 8.2. Ограничения

Edge TTS — изменяемый внешний сервис, доступ через сторонний клиент не гарантирует вечной бесплатности/совместимости. Изолировать сетевой адаптер. Не вводить фиктивную гарантию доступности. Проверка подключения — обязательный ранний технический результат, а не основание отложить всю читалку.

## 9. Надёжность и проверки

- Копия книги, текстовая модель, пометки и черновики не теряются после штатного закрытия/смерти процесса/обновления APK. Схема данных версионируется; не использовать разрушительную миграцию с удалением пользовательских данных.
- Не записывать текст романа, комментарии и аудио в обычные диагностические логи. Диагностика: версии, этапы, коды ошибок, размеры/счётчики без содержимого.
- EPUB распаковывать безопасно, не допуская выхода путей за каталог, не выполнять скрипты книги, не загружать внешние ресурсы автоматически. Локальная книга не должна получать доступ к данным приложения.
- JVM-тесты для содержательной логики: Unicode/абзацы/контекст, объединение, стабильный порядок, дубликаты/редакции, сериализация, отмена устаревшего TTS-запроса, ключи кеша. Не писать тесты ради количества.
- Android-проверки: импорт SAF, выделения/локаторы после смены шрифта и перезапуска, удаление/очистка, экспорт и lifecycle аудио. Автоматизировать доступное, остальное — краткий ручной чек-лист Honor.
- Сборки: `assembleDebug`, `testDebugUnitTest`, `lintDebug`; `assembleDebugAndroidTest`, если добавлены instrumentation-тесты. Фактические имена задач уточнить по проекту. Не менять настройки lint ради сокрытия ошибок.
- В каждом отчёте отделять: собралось; unit/lint PASS; Android runtime PASS/FAIL/NOT_RUN; проверено на Honor пользователем. Никаких «всё работает» только по сборке.
