База: `54481b8ed59d62dcbf7cbe919f2ab43ea587d3a2`. Работа продолжается в `codex/jjreader-p0-feasibility`, Draft PR #1; итоговый commit — в DELIVERY.json. P1–P5 и merge не выполняются.

**Зафиксированный дефект 0.1.0:** на Honor / Android 15 чтение FAIL по сообщению пользователя. Любой EPUB и встроенный пример показывали XML parser error. В облаке причина воспроизведена двумя падающими регрессиями: строгий XML-парсер после настоящего SafeHtml сообщает незакрытые `link` и `meta`. Исходный минимальный XHTML и главы EPUB валидны до обработки. Предыдущие HTML/импортные тесты этот путь не проверяли.

## Исправление

- ReadiumEngine передаёт фактический MIME каждого HTML-ресурса в SafeHtml. Для `application/xhtml+xml` используются XML parser, XML serialization и escape mode XHTML; `text/html` сохраняет HTML-режим. MIME XHTML не подменяется.
- Сохраняются namespace / `xml:lang` / `epub:type`, локальные CSS, изображения, ссылки, абзацы, кириллица, NBSP и составные Unicode-символы. XML-декларация согласована с UTF-8; внешняя DTD не нужна, именованные HTML-сущности сериализуются в допустимый XML. Прежнее ограничение прототипа на входной UTF-8 не расширяется.
- Фильтр скриптов, событий и внешних адресов, CSP, проверка DOM/модели остаются. EPUB на диске, IDs книг, пометки, черновики и схема данных не переписываются. Отдельного исправления несовпадения модели после успешного разбора синтетических XHTML не потребовалось.
- При обновлении сохраняются пакет `com.fantadrom.jjreader` и debug-сертификат code 1. Ключи не экспортируются. Исходники и материалы брендинга сохранены.

Проверка injector использует test-only reflection к внутреннему API зафиксированной библиотеки и Robolectric API 35 для Android Uri. Это настоящий код инъекций Readium, но JVM/Robolectric и Node не являются проверкой WebView на устройстве. Для Node больше нельзя получить общий PASS только по самостоятельно созданным HTML-страницам: обязательны файлы из JVM-цепочки SafeHtml/Readium.

Новый Android-тест запускает отдельную unexported debug Activity с настоящим navigator, не трогая текущую книгу и пометки пользователя. Он ждёт контрольный текст всех трёх ресурсов и загрузку локальной иллюстрации, проверяет MIME, отсутствие parsererror и согласование DOM/модели. Дополнительно повторно читает final response через тот же WebViewClient по текущему URL и строго разбирает его после всех инъекций. Программное DOM-выделение должно дать непустой Readium selection/locator и точный якорь. Тест собран, его выполнение не объявляется PASS.

## Проверка на Honor

1. Обновить APK без удаления приложения и очистки данных. Для локальной сборки использовать прежний локальный ключ.
2. Открыть «Пример P0»: видны кириллица, три раздела и иллюстрация; красного XML-блока нет.
3. Открыть ранее не работавшую книгу: текст виден, parsererror отсутствует.
4. Создать пробную пометку, увеличить шрифт, перезапустить, открыть пометку: переход к тому же вхождению.
5. Проверить экспериментальный процент; при сохранении несовпадения DOM/модели зафиксировать его отдельно, защиту не отключать.
6. После успешного чтения проверить Дмитрия и Светлану, затем Home/возврат: звук останавливается и сам не возобновляется.

P0 остаётся на приёмке до этой проверки. Ограничение бесшовной прокрутки между ресурсами не устранялось; архитектурное решение остаётся открытым.
