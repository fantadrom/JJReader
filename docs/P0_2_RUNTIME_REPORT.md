## Причины и исправления шести FAIL

| FAIL | Найденное и сделанное | Предел доказательства |
|---|---|---|
| 1. А− / А+ | Chromium отклонял CSP-источники `https://readium_assets` / `https://readium_package`: подчёркивание недопустимо в host-part CSP. Readium CSS/JS блокировались. Источники исправлены; единицы проверены в библиотеке: `Length.Percent(1.0)` = `100%`, диапазон редактора 0.1–5.0. Умножать старые значения на 100 нельзя. Добавлен явный `fontUnits=readium-scale-v1` без изменения существующего масштаба. Последняя preference применяется до асинхронной работы с локатором. | CSP-дефект воспроизведён настоящим Chromium; computed font size меняется 16 → 23.2 px. Honor code 3 NOT_RUN. |
| 2. «Readium не вернул выделение» | При заблокированном JS `window.readium` отсутствовал. Дополнительно прежний код снимал DOM и native selection в разные моменты после нескольких await. Теперь один снимок диапазона/цитаты/resource/documentId/session получается до закрытия ActionMode; selectionchange сохраняет актуальный диапазон до потери фокуса. Сохраняются проверки книги, поколения DOM, границ, hash и точной цитаты. | Browser проверяет точный диапазон при пустом native API. Настоящий Android long-press/ActionMode добавлен, собран, NOT_RUN. Поиск первого совпадения цитаты не используется. |
| 3. Выгрузка / перезапуск | Старое событие currentLocator могло перезаписать точный локатор; при заблокированном JS текстовый переход также не применялся. После готовности правильного DOM выполняются точный переход, два animation frame и проверка видимости; только затем разрешается запись позиции. Добавлены revision gate и проверки отмены после await; прежняя Activity не может записать запоздалый viewport. Позиция сохраняется по ходу чтения и запрашивается при onPause, без зависимости от onDestroy. Во время редактора/IME запись viewport заморожена; после закрытия восстанавливается текстовый якорь. | Browser resized viewport PASS. Исходная причина NETWORK на Honor пока неизвестна; она не приписывается Microsoft или сети пользователя. |

## Защита и данные

XHTML/XML-исправление сохранено. MIME не подменяется. Скрипты книги и обработчики событий удаляются; CSP по-прежнему запрещает inline script, connect, frame, object и form. Из-за виртуальных имён с подчёркиванием trusted Readium JS/CSS разрешены по точному HTTPS-пути / префиксу пути, локальные ресурсы — через `'self'`. ReadiumEngine независимо отклоняет все внешние HTTP-ресурсы, WebView обслуживает публикацию через локальный resource interceptor. Защита не отключена целиком. Chromium проверяет загрузку движка и отказ inline-скрипту книги без исходящих запросов.

Схема reader.json остаётся 1; добавлены поля позиции и единиц шрифта. Копии EPUB, ID, пометки и черновики не удаляются и не пересоздаются. Кеш ограничен 12 MP3, сетевой блок — 2 MiB; cache hit отмечен отдельно от network. Повтор имеющейся записи не требует сети. Повреждённое аудио удаляется из кеша для явного повторного запроса. Endpoint, публичный token, голоса, параметры и сообщения протокола не менялись; Python в APK не добавлялся.

Кнопка **«Диагностика TTS» → «Копировать»** выдаёт время UTC, ID/поколение, голос, этап, duration, cache/network, HTTP status, WebSocket close code и классы исключений/причин. Последний отчёт сохраняется локально; сообщения исключений, текст, SSML, URL и Cookie/authorization не сохраняются. Это не телеметрия и не отправка данных разработчику. ADB для получения ошибки не требуется.
