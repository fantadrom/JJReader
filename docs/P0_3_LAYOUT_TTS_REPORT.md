## Ширина

Проверены исходники и реальные assets Readium 3.4.0: EpubPreferences предлагает columnCount/pageMargins, но не параметр maxLineLength. В ReadiumCSS-after.css scroll-правило оставляет body с max-width 40rem!important; pageMargins=2 дополнительно удваивает адаптивный gutter. ColumnCount.ONE не устраняет этот предел. В реальном Chromium до исправления root/innerWidth увеличиваются корректно: это воспроизведённый CSS-предел, а не застывший viewport в этом runner. Устаревший viewport конкретного Honor без устройства исключить нельзя.

В собственном runtime-мосте добавлено только правило для `:root[style*=readium-scroll-on] body`: max-width:none и горизонтальные padding 16px. EPUB, CSP, кнопки, жесты, вертикальная прокрутка, font preferences и восстановление позиции не менялись. Правило устанавливается до измерения/восстановления якоря; сохраняются DOM-диапазоны и шаблоны пометок/подсветки. Выбраны фиксированные небольшие CSS-поля, поэтому их ширина не растёт вместе с viewport.

## Повтор и отмена

Один блок: максимум 3 сетевые попытки, задержки 500/1500 ms; максимум один запрос синтеза благодаря существующему Mutex кеша. Один prefetch остаётся изолирован от текущего воспроизведения. Курсор двигается только после окончания аудио, поэтому успешные предыдущие фразы не проигрываются заново. После окончательного отказа «Продолжить» начинает новый ограниченный цикл с непрочитанной фразы.

Allow-list: DNS, CONNECT, TIMEOUT, IO_SocketException, IO_EOFException, HTTP 408/429/502/503/504. FRAME_HEADER/FRAME_SHORT, параметры, TLS (включая сертификат), авторизация, закрытия протокола и остальные ошибки не повторяются. Retry-After поддерживает секунды и HTTP date. Значение до 5 s учитывается как нижняя граница задержки, максимум ожидания backoff 10 s за цикл. Если сервер требует дольше 5 s, цикл прекращается, а не повторяет раньше. Общий верхний предел синтеза — 3 × 30 s плюс backoff; задержки и запросы отменяемы.

Каждый вызов synthesize создаёт новый WebSocket/ConnectionId и отдельный ByteArrayOutputStream. Только завершённый turn.end с проверенным размером публикуется атомарно в кеш. Пауза/Home/блокировка/смена книги или голоса/новый старт отменяют coroutine, socket и backoff. CancellationException не повторяется. «Повтор подключения N/3» показывается на основном потоке с проверкой отмены. Endpoint, голоса, заголовки, параметры синтеза и токен-алгоритм сохранены.

## Локальная диагностика schema 2

Сохранена кнопка копирования. Session UUID + generation + порядковый block связывают попытки; каждая имеет собственный id, networkAttempt/maxAttempts и source. Cache hit имеет networkAttempt=0 и synthesis=cached. Поля openedMs, firstAudioMs, synthesizedMs, playbackReadyMs, playbackMs, completedMs отражают прошедшее время от начала попытки. playbackReady — начало применения подсветки; playbackMs пишется только после MediaPlayer.start. synthesis=success не равен playback=completed. Для частичных ответов доступны audioBytes/audioFrames, для отсутствующего аудио — нули; HTTP/close/классы причин и исход attempt сохраняются отдельно.

Категории socket_error, stream_closed, timeout определяются только по классу исключения. Причины connection_reset или блокировки не угадываются из message. Поздний close обновляет только метаданные своей строки, а старые retry/session не добавляют записи в новую сессию. Хранится максимум 32 записи. Старый сохранённый JSON schema 1 читается/копируется без преобразования до первой новой сессии; его версия явно остаётся 1. Текст книги, комментарии, SSML, message/stack trace, URL/токены/cookies не экспортируются; отправки разработчику нет.
