## Подключение к Readium

Проверка API выполнена через создание производного EPUB: Readium открывает его как обычную локальную Publication с **одним** элементом readingOrder — `unified.xhtml`. Затем используются существующий `EpubNavigatorFragment`, его CSS/JS-инъекции, выделение и decorations. Ни Compose navigator, ни новый WebView-движок не вводились.

`UnifiedDocument` строит DOM из линейных ресурсов сохранённой модели в исходном порядке. Каждый раздел получает `section#jj-source-i` и внутренний `div[data-jj-body]`. Нет автоперехода на следующую страницу при достижении низа: содержимое соседних разделов действительно существует в одном прокручиваемом документе. Граница не вносит обязательный разрыв или техническую подпись. Перенесённый body освобождается от фиксированной ширины, высоты, полей и позиционирования корневого контейнера.

Источник EPUB и его UUID остаются в `BookStore`; производная Publication не импортируется как новая книга. Сохранённые главы, канонические тексты и `reader.json` не мигрируют. Меню диагностики позволяет переключить unified/legacy без переимпорта. По умолчанию включён unified; неподдерживаемый случай даёт понятное сообщение и предложение открыть legacy.

## Координаты и данные

| Уровень | Адрес и назначение |
| --- | --- |
| Постоянный | UUID книги + исходный раздел + локальный диапазон `[start,end)` code points + hash/quote; прежняя модель v1 |
| Производная карта | Исходный href, индекс, длина, prefix, textHash, ID оболочки; schema1, converter `unified-v1`, generation |
| Отображение | Ресурс Readium 0 / `unified.xhtml`, sourceChapter внутри него, DOM Range в UTF-16 |
| Процент | prefix последнего видимого исходного раздела + его последний видимый offset, делённые на исходный total |

Общий `RenditionAdapter` обслуживает пометки, переходы, viewport/процент, TTS и исходные локаторы. Старые href/DOM-пути не применяются прямо к объединённому DOM: локатор отображения пересоздаётся из проверенного исходного диапазона. Новые постоянные локаторы получают оригинальный href; технические section/div удаляются из структурного пути для совместимости с legacy. Существующие ID, комментарии, цитаты и количество пометок не переписываются. Неоднозначная или несовпадающая привязка сохраняется с сообщением о недоступности перехода и возможностью legacy.

Для каждого раздела канонический текст проверяется до и после DOM-преобразования. JS индексирует каждый body отдельно по прежним правилам v1, без NFC. Prefix вычисляется из **проверенных локальных длин**, без нормализации текста двух разделов вместе. Emoji/ZWJ и комбинируемые символы расширяются до границы графемы; DOM UTF-16 переводится в code points. Одинаковые цитаты различаются локальными координатами и структурой, а не первым совпадением по книге.

На точной глобальной границе выбирается следующий непустой раздел; конец total адресует конец последнего непустого. Пустая оболочка сохраняется, но не создаёт фиктивный текстовый диапазон: переход выбирает следующий непустой либо последний символ предыдущего. Полностью пустая книга показывает 0% и не предоставляет текстовый якорь. Межраздельное выделение явно отклоняется: «Пометка должна находиться внутри одного исходного раздела». Неполная цитата не сохраняется.

`ReaderSession` проверяет documentId, generation, sourceChapter, текст/hash и revision. Смена видимого исходного раздела внутри общей ленты не считается сменой ресурса Readium. Restore ждёт готовности документа, шрифтов и локальных изображений, затем устойчивой положительной геометрии и ACK. Сохранённая читаемая точка защищена от подмены началом предыдущего раздела при упоре прокрутки в конец короткой книги. Пользовательский жест снимает это закрепление. Сохраняется защита P0.6 от устаревших операций и недостоверного capture.

## Ссылки, CSS и поддерживаемая область

Относительные пути разрешаются относительно **оригинального файла**. Локальные изображения, CSS и шрифты копируются в `source/<original-path>` производного EPUB; ссылки на исходные линейные XHTML/фрагменты становятся внутренними `#jj-i-id`. Исходные ID и IDREF (`for`, `headers`, ARIA) получают префикс раздела. TOC Readium преобразуется с сохранением названий и фрагментов; простой диалог доступен в диагностике. При отсутствии авторского TOC диалог явно подписан «Разделы — оглавление отсутствует».

Обычные CSS-селекторы ограничиваются body конкретного раздела; ID-селекторы переписываются. Поддержаны локальные @import, url(), @media/@supports, базовые html/body/:root, классы, inline-оформление, заголовки, абзацы и @font-face без конфликтов. page-break/break/колонки снимаются, @page игнорируется для непрерывного режима. Одинаковые классы/ID двух разделов с разными цветами проверены в Chromium. Загрузка локальных изображений сделана eager, чтобы после restore не менялась высота из-за отложенной иллюстрации.

Ограничения, для которых предлагается legacy:

- повторяющийся href readingOrder неоднозначен для старой модели; сохранённая модель не дедуплицируется;
- нелинейный itemref внутри уже сохранённой модели не перенумеровывается; произвольные XHTML из ZIP, nav и служебные файлы в конец не добавляются;
- ссылка на HTML вне линейной модели (в том числе отдельный нелинейный файл сносок) требует legacy; локальная сноска в линейном DOM и обратная ссылка поддержаны;
- сложные/экранированные селекторы, неподдерживаемые at-rule, абсолютная/фиксированная или вертикальная вёрстка и конфликтующие font-face отклоняются; полной поддержки издательского CSS нет;
- внешние CSS/import/ресурсы не разрешаются. Прежние SafeHtml, запрет активного содержимого, ограничения ZIP/путей и CSP сохранены. SVG/MathML/скрипты не добавлены.

Это консервативное преобразование для обычного текста, а не универсальный CSS parser. Свойства исходных html-классов, сложные шрифтовые зависимости и нестандартные форматы не покрыты общей гарантией. Изображения/шрифты реальных книг дополнительно проверяются на Honor. Итог сериализуется XML и проверяется строгим XML parser **после настоящей инъекции Readium**.

## Подготовка и кеш

Подготовка идёт на IO dispatcher с состоянием загрузки и отменой; нет произвольного 12-секундного таймаута для открытия большой unified-книги. Ключ кеша включает SHA-256 источника, UUID книги, hash исходных href/текстов, converter и model1. В частном каталоге приложения создаётся `.stage-UUID` с EPUB, map.json и ready.json; файлы синхронизируются и каталог атомарно переименовывается в готовое поколение. Перед использованием проверяются hash EPUB и карты. Частичный/повреждённый кеш пересоздаётся; отменённая подготовка удаляет staging, оставшийся после остановки staging убирается при следующей подготовке. Источник и reader.json не затрагиваются.

Повторное открытие проверяет источник/готовый кеш, поэтому это не нулевая работа. Поворот и размер шрифта не пересобирают EPUB. В памяти остаётся весь DOM книги; ленивые координатные индексы ограничены LRU из восьми разделов с защитой текущего подтверждённого якоря. Виртуализация глав не реализована. Для книг с большим количеством изображений затраты могут быть выше измеренных текстовых фикстур.

## Озвучка и диагностика

Пробный предел **пять фраз** сохранён. Фразы разбиваются отдельно в каждом исходном разделе; очередь может добрать следующие из соседнего непустого раздела. `Phrase.chapter` указывает локальную модель для подсветки и прокрутки. Естественная прокрутка через стык не сбрасывает очередь. Явный переход по TOC/пометке/ссылке меняет revision/navigationSerial и отменяет старую подсветку. Проверка перед JS go не позволяет запоздалому callback вернуть пользователя к прежней фразе.

Endpoint, голоса/токен, SSML, аудиокеш, retry и рабочий сетевой маршрут Edge не изменены. Переход на следующую главу после исчерпания пяти фраз относится к будущему полному TTS. Сетевые запросы Microsoft в этом этапе не выполнялись; прежний CONNECT 403 облака не доказывает недоступность голоса.

Существующий диагностический диалог показывает фактические versionName/code, unified/legacy, converter/generation, model1, reader trace schema3, Android/WebView runtime и prepareMs/cacheHit/openMs. Трасса различает `renderedResource` и `sourceSection`; поля target/observed/diskChapter относятся к исходным индексам, dom в unified не подменяется исходным индексом. Для ACK/REJECT/RECOVERY добавлено durationMs. Экспорт не содержит текстов, цитат, комментариев, названий книг, путей, SSML или свободных exception messages; отправки логов нет.

## Воспроизведение в Windows

Требуются JDK25, Android SDK37/Build Tools37, Python3.10+, Node и установленный Chromium/Chrome/Edge. Версии Android/Readium не обновлялись. Подпись локальной сборки может отличаться: для обновления установленной облачной версии используйте приложенный совместимый APK. Не удаляйте приложение ради конфликта подписи.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :edge-protocol:test :app:lintDebug :app:assembleDebugAndroidTest
python tools\generate_continuous_fixtures.py
.\gradlew.bat :app:testDebugUnitTest --tests "*UnifiedBenchmarkTest" -PjjBenchmark=true
python tools\prepare_unified_browser.py
npm ci --prefix tools
$chrome = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
node tools\verify_unified.cjs work\aar-assets $chrome work\unified-browser
node tools\benchmark_unified.cjs work\aar-assets $chrome app\build\unified-benchmark work\performance
```

Если AAR не найден автоматически, передать `--aar "C:\путь\readium-navigator-3.4.0.aar"` из Gradle cache. `prepare_unified_browser.py` извлекает assets и только созданные тестами EPUB. Benchmark в Windows сохранит времена и JS heap, но `/proc` отсутствует: renderer RSS/HWM будут 0 (= недоступны, не нулевое потребление). JVM результаты: `app/build/unified-benchmark/results.json`; браузер: `work/performance/browser-benchmark.json`. Обычный тестовый набор после запуска одного benchmark можно вернуть первой командой.

Необязательные команды разработчика при подключённом Android:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
powershell -File tools\android_process_restart.ps1 -Unified
adb shell dumpsys webviewupdate
adb shell dumpsys meminfo com.fantadrom.jjreader
```

`dumpsys meminfo` полезно снять после первого открытия, после повторного и после серии reflow; WebView renderer может иметь отдельный PID и не полностью учитываться в app PSS. Время подготовки/открытия видно в диагностике, времена restore — в reader trace durationMs. Для ручной проверки достаточно [HONOR_CHECKLIST.md](HONOR_CHECKLIST.md), сложный стенд не требуется. Личный роман и текстовые системные логи не включать в публичные артефакты.
