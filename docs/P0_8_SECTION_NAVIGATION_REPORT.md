Версия **0.1.9-p0 / code10**, база `53d860efddaf4b6fc73ee17a658b6c613a3c83a0`, прежняя ветка и Draft PR #1. Commit результата указан в DELIVERY.json. ApplicationId и совместимая debug-подпись сохранены: SHA256 сертификата `06ba3132107a954a4640ad60a29138b297449a6172bb763b8832293dc1c727ef`. SDK, зависимости, движок и branding не обновлялись. Это принятое пользователем решение заменяет требование общей ленты P0.7. ## Предыдущие факты Honor

Code9 на Honor ABR-LX1 / Android15 вновь открывает книги; пользователь подтвердил unified-переходы, landscape, оглавление, доступные пометки, положение/повороты/шрифт и TTS через границу. Ручной переход к пометке останавливает очередь — это принято. Кнопки в большом unified показались медленными, причина на устройстве не измерена. Доступ к старым копиям, иллюстрации, ссылки/сноски и возврат ещё **не были подтверждены**. Эти результаты не переносятся автоматически на code10.

## Readium и жест

Проверены публичные API Readium3.4.0: EpubNavigatorFactory.createFragmentFactory(listener/configuration), Navigator.go(Link/Locator), evaluateJavascript, InputListener.onDrag. onDrag не предоставляет надёжного состояния DOM-края и полного touchcancel/multitouch/selection lifecycle; готового вертикального переключателя разделов нет. Используется тот же стабильный EpubNavigatorFragment, исходная Publication и публичный evaluateJavascript. Fork, новый WebView, Java-интерфейс книги и Compose navigator не добавлялись. Горизонтальные page turns при scroll отключены через публичную configuration.disablePageTurnsWhileScrolling.

Доверенный `section-navigation.js` устанавливается вместе с существующим LocatorBridge в текущий документ. События touch наблюдаются пассивно: обычный scroll, инерция и выделение не перехватываются. Touchstart запоминает уже достигнутый верх/низ; жест, только достигший края, не переключает документ. Инерция без нового touchstart не создаёт запрос. После последнего scroll выдерживается 120ms перед постановкой нового жеста на учёт, чтобы не считать движущийся документ устойчивым краем.

Порог — **48 CSS px**, вертикальная составляющая минимум в 1,5 раза больше горизонтальной; жест до 650ms. Readium viewport соответствует device-independent CSS ширине, поэтому это плотностно-независимые единицы, не физические пиксели дисплея. Нужна проверка ощущения порога на Honor. Multitouch, touchcancel, непустое выделение, long press, link/control/decorations не создают переход. Очередь содержит один жест; busy блокирует повтор до завершения/отказа. Первая/последняя граница лишь снимает блокировку, циклов нет.

MainActivity читает уже установленный bridge коротким JS-запросом каждые 40ms в RESUMED. Тяжёлая проверка модели/viewport остаётся в прежнем 350ms capture-потоке. Кандидат связан с documentId и принимается только текущей ready-сессией. Пустой idle-poll снимает оставшуюся DOM-блокировку отменённого/предзагруженного старого документа; пока controller busy, polling кандидатов не выполняется. SectionNavigation сериализует жесты, кнопки, TOC, пометки, ссылки и TTS через один mutex; инициатор сохраняется. Ручной переход сбрасывает старую речь. Поворот/Home/смена книги отменяют операции; ReaderSession revision/ACK препятствуют позднему commit. Кнопки обоих направлений открывают **начало** целевого ресурса, только обратный краевой жест открывает конец.

## Хвост и положение

В конце body добавляется пустой технический div с aria-hidden. Он не содержит текста, не меняет EPUB, hashes/модель, цитаты или речь. По последнему видимому текстовому glyph/image и фактическим innerHeight/scrollHeight рассчитывается хвост; учитываются поля издателя, короткие страницы, шрифт, resize и загрузка картинок. Последняя строка внизу прокрутки оказывается около верхней границы viewport. Для большой конечной картинки доступен её естественный конец; изображение не обрезается и не заменяется концом предыдущего текста. ResizeObserver не требует опроса всего DOM каждый кадр.

Текстовая позиция остаётся исходным разделом и code-point диапазоном модели v1. DOM — UTF-16; прежнее преобразование/grapheme/quote/hash/revision и положительный устойчивый ACK сохранены. Переход к границе создаёт исходный диапазон, затем после открытия реального документа разрешает его в фактический DOM. Декоративный хвост не увеличивает процент: используются последний видимый code point, source prefix и исходный total. EOF последнего текстового ресурса даёт 100%.

Для image-only/полностью пустых ресурсов не создаётся ложная цитата. В reader.json добавляется `positionKind=visual`, `visualPosition {schema:1,chapter,end,locator}` с локатором Readium; старые пометки и старый positionV2 не удаляются. При восстановлении этот discriminator имеет приоритет. Начало/конец подтверждаются готовым текущим DOM, fonts/images и устойчивой положительной геометрией. Внутри иллюстрации сохраняется допустимый локатор движка; это приблизительная визуальная позиция, а не текстовый якорь. При следующем текстовом capture discriminator снимается. Пустая книга имеет 0% и доступные переходы/иллюстрации.

Там, где текст виден, он остаётся основанием позиции; выход в нетекстовую область не переносит текущую позицию в прежний раздел. Ошибка перехода не объявляется успехом, если ready относится к другому ресурсу или lastRestoreCode сообщает отказ. Короткие/пустые/изображения — отдельные доступные ресурсы, не пропускаются жестами; TTS пропускает только отсутствие фраз. Это не искусственное разбиение больших XHTML: книга из одного огромного ресурса получит ограниченный выигрыш.

## Режим и озвучка

ReadingMode однократно записывает modeSchema1/mode=sections при обновлении code9, независимо от прежнего unified=true. После этого явный unified выбор сохраняется при перезапуске. Старый флаг не удаляется, данные книг не мигрируют. В диагностике режим `sections` отличается от старого `legacy`. Существующее меню сравнения выбирает unified или новый раздельный режим; дополнительного экрана настроек нет.

Очередь по-прежнему ограничена **пятью фразами**, с разбиением в каждом исходном разделе отдельно. Перед началом фразы другого ресурса SectionNavigation инициирует TTS-переход через ReaderSession и ждёт ACK; только затем ставятся highlight/scroll и запускается готовый MediaPlayer. Собственный переход TTS не сбрасывает очередь. Ручная ссылка/пометка/TOC/кнопка/жест сбрасывает её, «Продолжить» не возвращает к старому месту. Обычная пауза и Home/блокировка оставляют только ручное продолжение; отменённый callback не включает звук после ухода в фон.

Endpoint, голоса, SSML, retry и кеш не менялись. Для instrumentation есть override **только debug ReaderRuntimeActivity** с локальным WAV через штатные SpeechQueue/MediaPlayer/highlight/navigator. Production Activity всегда возвращает null и использует прежний Edge audio/cache. Локальный тест не доказывает работу Microsoft, сетевые пробы не выполнялись.

## Старые копии и дедупликация

Команда «Книги» встроена в существующую верхнюю строку, доступна после ошибки открытия. BookStore сканирует UUID-каталоги books-v1, не только current.json. JsonReader потоково читает title/schema и количество notes, пропуская канонические главы и комментарии без загрузки всего каталога в память. Список показывает имя, число пометок, короткий ID и текущую запись; повреждённые записи помечаются недоступными. BookStore.entries не создаёт NoteStore/reader.json, не исправляет, не объединяет и не удаляет старые дубли.

Открытие записи использует её прежний ID/модель/EPUB/NoteStore. Место покидаемой книги захватывается, ручные операции и речь отменяются. current.json меняется атомарно **после подтверждённого чтения/visual readiness** новой сессии. Открытие списка/отмена выбора не меняют current.json. Ошибка/отмена нового открытия не выдаёт новый ID за успешно открытый.

«Открыть EPUB» и «Пример P0» проходят один путь: staging в IO, потоковый SHA256 исходных байтов, проверка доступных внутренних исходников. Даже отсутствующий/устаревший metadata hash не исключает старую копию: хеш перепроверяется по файлу, ZIP проверяется. Имя/URI/title и derived EPUB в совпадении не участвуют. Ноль совпадений — новый импорт; одно — старый ID; несколько — явный выбор с количеством notes/ID. Изменённые байты — новая копия. Старые дубли не объединяются. Хеширование сейчас отдельным проходом после копирования и повторно для кандидатов: это дополнительный IO, не аллокация всего EPUB через readBytes.

Импорт/выбор сериализуются busy и openingJob; временный файл удаляется в finally. Отменённый собственный новый импорт, ещё не ставший активной книгой и не имеющий reader.json/current, удаляется адресно; существующие note-bearing/current копии не являются материалом очистки. При обычной ошибке открытия новая исходная копия сохраняется, чтобы работали резервный режим и последующий выбор. Массовой очистки книг/derived кеша нет.

## Сравнимые измерения

Стенд: Linux headless Chromium **154.0.8037.57**, настоящие Readium3.4.0 JS/CSS и injected XHTML, 430×500 CSS px, шрифт100%, полностью синтетический EPUB **3 025 092 CP / 200 ресурсов**; крупнейший исходный XHTML **28 152 байта / 15 126 CP**. Один и тот же файл для трёх режимов: sections; контроль отдельных документов без хвоста; unified. Android/WebView/Honor не измерялись. Последний известный Honor WebView155.0.8059.43 относится к code9, не к этому стенду.

По три новых browser context на режим. В каждом — первое и повторное открытие DOM, затем **10 последовательных переходов кнопкой и отдельно 10 краевых переходов**, затем три размера шрифта. Итого по 30 переходов каждого вида на режим. Для unified/control столбец «край» — эквивалентный явный переход к следующему исходному диапазону/документу: их собственный краевой жест отсутствует. OS cache не сбрасывался; «повторное» здесь означает второй DOM в том же browser context, а не Android warm start. BackForwardCache выключен; JS heap снят CDP после явного GC. Native Fragment/prefetch, загрузка BookStore-модели и до40ms native polling в эти времена не входят. Режимы проходили последовательно, без параллельной Gradle-сборки; общая нагрузка облачного хоста не фиксирована.

Один unified font-reflow не подтвердил устойчивую геометрию в существующем ACK-бюджете (`LAYOUT_UNSTABLE`); он сохранён отдельно в failures JSON и не превращён в успешную длительность. Дополнительные исследовательские прогоны тоже встречали этот отказ. Защита ACK не отключалась, преобразователь unified не оптимизировался. Sections/control в законченной серии не имеют отказов ACK. Это результат настольного стенда, не новый подтверждённый сбой Honor.

Медианы разделения кнопки sections: **load 207ms / ACK94,5ms**; control **182,5 /91,5ms**. Краевой sections: load188,5 / ACK90ms; оставшееся — моделирование touch/получение запроса. Выброс 1560ms пришёлся преимущественно на загрузку документа; окончательные сырые значения доступны в `checks/sections-performance.json`. Разброс хоста заметен, добавочную цену хвоста нельзя объявить постоянной задержкой по разности медиан. Readium на телефоне использует свой ограниченный пул/соседние ресурсы, а desktop-стенд загружает новый документ: это консервативная проверка нового DOM, не эмуляция native page cache.

Unified prepare в отдельном JVM/Robolectric экспорте заняла 2555ms (одна подготовка, не серия); в основном sections derived-подготовки нет. Таблица открытия DOM её не включает. JS heap — только JavaScript, не весь DOM/layout/RSS и не PSS Android. Память процесса/WebView на телефоне — **NOT_RUN**.

Вывод: раздельный режим в доступном стенде существенно уменьшает стоимость открытия/шрифта большого текста. Его переход не бесплатен: заметную часть составляют новый DOM/Readium injection и обязательный ACK. Уже загруженный unified меняет текстовый диапазон быстрее. Цель сравнения с прежним отдельным DOM достигнута как контроль, но обещать конкретную скорость или устранение всех задержек Honor нельзя; выбросы загрузки остаются ограничением, требующим native замеров. Книга с одним большим XHTML, реальный роман/иллюстрации и очень много пометок требуют отдельной локальной проверки.
