## Исправленное поведение

| Операция | Размещение |
| --- | --- |
| Правое касание при показанном конце и запасе >= обычной строки | `TAP_FORWARD_START` → `RESOURCE_START` следующего ресурса |
| Левое касание при показанном начале содержимого | `TAP_BACK_END_PAGE` → `END_PAGE` предыдущего ресурса |
| Обратный вертикальный жест | `GESTURE_BACK_END` → `END_TOP`, прежний конец около верха |
| Пометка/TTS/произвольная сохранённая позиция | `ANCHOR`, прежняя точная привязка без нового отступа |

`pageStep` больше не требует физического maxScroll или scrollY=0. Начало — верх первого значимого элемента/глифа: естественные поля либо ранее выровненный заголовок не требуют дополнительного касания. Первая частично обрезанная строка не считается показанным началом; иллюстрация перед заголовком имеет приоритет. Конец — измеренный нижний край последнего значимого содержимого, включая img, таблицу и подпись. Проверка последнего текстового символа не пропускает иллюстрацию после него. Пустой ресурс доступен отдельно и не пропускается автоматически.

Правый переход допускается при нижнем крае в viewport и свободном месте >=lineHeight; если край уже выше viewport в хвосте, возвращать его в экран не нужно. Допуск округления —1 CSS px. При частично видимом конце либо меньшем запасе остаётся обычный шаг `viewportHeight-lineHeight`. Первый/последний ресурс ограничиваются native-проверкой диапазона; отсутствие перехода не создаёт цикл и сохраняет действующее семантическое размещение.

`END_PAGE` вычисляется заново как `clamp(contentBottom+min(4L,H/2)-H,0,maxScroll)`. В длинном тексте виден заключительный заполненный экран; в коротком начале не уезжает за верх ради точного запаса. Для высокой иллюстрации показывается нижняя часть и сохраняется прокрутка вверх. Физический хвост P0.8 не уменьшен; для высокой завершающей иллюстрации/крупного содержимого при необходимости добавляется место для требуемого запаса. `END_TOP` для таких элементов вычисляет прежнюю позицию `max(top,bottom-H)`, поэтому увеличение доступного хвоста не заменяет размещение обратного жеста правилом касания.

## Источник подтягивания и сохранение

Прежний `locator-bridge.scrollTarget` выравнивал первый глиф по верху viewport при запросе и в ходе ACK. Именно наш мост подтягивал заголовок; начальный небольшой отступ давала текущая раскладка EPUB/Readium. Без EPUB пользователя конкретное CSS-правило не объявляется причиной.

Явный `RESOURCE_START` теперь удерживает scrollY=0, сохраняя естественный отступ текущей раскладки, и проходит ту же проверку документа/revision/цитаты/устойчивой геометрии/ACK. Начальная книга без прежней позиции также входит таким способом. Начальный native locator семантической позиции содержит только href ресурса: Readium не получает команду сначала показать текстовый якорь в другом размещении. TOC без фрагмента также считается входом в ресурс; TOC с фрагментом сохраняет точный переход. Общая функция выравнивания произвольных якорей не получает нового фиксированного отступа. Глобальная переработка CSS не добавлялась.

К исходному текстовому якорю или визуальной записи добавляется необязательный `entryPlacement:{schema:1,kind:RESOURCE_START|END_PAGE}`. Координата scrollY **не хранится** в пользовательской позиции. При повороте, шрифте, панелях или новом процессе способ размещения вычисляется по новой DOM-геометрии. Pin/capture удерживает семантическую границу, а не подменяет её первой видимой строкой. Тап центра и яркость не сбрасывают её, пока содержимое не двигалось. Обычная прокрутка/шаг внутри документа возвращают обычное сохранение якоря; неизвестный будущий marker игнорируется. Старые записи без признака читаются как прежде, миграции нет.

После подтверждения ACK поздний `restoreStatus`/`visualStatus` больше не прокручивает подтверждённую границу заново. Устаревший revision/document отвергается до записи; подтверждение visual теперь также проверяет documentId. Позиция пустого/image-only ресурса остаётся визуальной, без фиктивной цитаты. При старом visual locator подтверждается документ после его фактического открытия.

## Измерения, отмена, диагностика

Ссылки на первые/последние глифы текстовых узлов и поддерживаемые значимые элементы строятся на текущий ресурс; не размечается вся книга. Документные метрики кешируются и не обходят DOM на tap/scroll/40ms poll. Инвалидация: смена документа, resize/панели, изменение стилей/текста/DOM, font ready и загрузка изображений. Собственный tail и декорации исключены из содержимого и не вызывают повторный обход своими атрибутами.

L берётся из обычного p/li/blockquote/td/figcaption/pre, не заголовка. Для `normal` — конечная положительная оценка `1.4*fontSize`, без обычного текста — body. Всё в CSS px. Расчёт не переносит физические пиксели Android в DOM.

Тап проходит через прежние ReaderSession/SectionNavigation, а не отдельный навигатор. Пока действие ожидает native-подтверждения, быстрый следующий контакт не добавляет второй переход. Ручные касания сбрасывают очередь TTS; автоматический переход TTS сохраняет прежнего владельца. Приоритет выделения/ссылок/пометок и яркости сохранён. Полка, SAF, дедупликация, модели пометок и сетевой TTS-протокол не перерабатывались.

Трасса различает перечисленные размещения; PAGE_STEP также показывает выбор обычного шага при частичном крае/недостаточном запасе; метрики разрешены по явному списку: lineHeight, viewport, contentTop/contentBottom, свободное место, видимость краёв, результат/ACK. Пиксельные измерения в диагностике не являются persisted position. Цитаты, текст, комментарии, URI и имена файлов не добавляются в диагностический журнал.
