# P1 — рабочая читалка и внутренняя полка

Версия **0.2.0-p1 / code11**, applicationId `com.fantadrom.jjreader`. Основа — master `67acede`, содержащий принятый пользователем P0.8; новая ветка `codex/jjreader-p1-reader-shelf`. P0 принят **пользователем**, не объявлен повторно проверенным средой. P1 требует новой проверки Honor. P2–P5 и merge P1 не выполнялись.

## Актуализация ТЗ

До реализации добавлена [актуальная редакция исходного ТЗ](JJReader_TZ.md). Изменены только необходимые положения и описание P1: отдельные ресурсы Readium/хвост/новый жест; выделение внутри ресурса; приоритет жестов; процент без хвоста и visual position; SHA256-переоткрытие/выбор дубля; пауза против ручного сброса TTS; сохранение всех существующих ID/данных; порядок P1. Обычные ссылки/сноски с возвратом обязательны, специальный popup-интерфейс не реализуется. Для P2 зафиксированы **логические главы TOC**, с ресурсом как запасной границей: ресурс и глава не отождествляются. Старый `Book.chapters` — список исходных ресурсов модели v1; P1 не меняет границы будущего контекста/объединения P2.

## Полка и SAF

Новая полка — простой список всех прежних books-v1 UUID-копий: название, исходное имя или дата внутренней копии, процент, количество пометок, короткий ID, текущая/недоступная запись. Новые импорты получают sourceName/importedAt как дополнительные поля schema1, без переписывания метаданных старых книг. Для старых записей, где процент не сохранялся, честно показывается «Место сохранено»; при открытии вычисляется и сохраняется текущий процент по принятой текстовой модели. Отсутствующий исторический последний видимый символ не выдумывается из номера ресурса.

Стартовая папка выбирается через OpenDocumentTree. SourceFolder сохраняет URI и пытается удержать **read-only persistable** разрешение; при неподдерживающем провайдере временный доступ используется без фиктивной гарантии. Можно просматривать подпапки и выбирать EPUB. Потеря доступа даёт понятное предложение выбрать папку снова; внутренняя полка остаётся доступной. Отмена не заменяет выбранную папку. Исходники открываются только на чтение, DocumentsContract.deleteDocument и общий storage permission не используются.

«Открыть файл» через SAF остаётся альтернативой. Путь P0.8 SHA256 сохранён: один идентичный исходник открывает прежний UUID, несколько совпадений требуют выбора с количеством notes/ID, изменённые байты создают отдельную книгу. «Пример P0» использует тот же путь. Сканирование полки не открывает все EPUB и не создаёт NoteStore. Позиции каждой копии независимы; current.json активируется после подтверждения готовности новой книги. При запуске возвращается последняя книга; при её ошибке видна полка с сообщением, при пустой библиотеке — выбор папки/файла.

«Действия» предоставляет сведения, **подтверждаемую очистку пометок** и **подтверждаемое удаление книги**. Очистка убирает notes/draft, сохраняет EPUB, позицию, настройки и процент. Текущий ReaderSession замораживается на время записи, чтобы старый capture не вернул очищенные пометки. Отмена диалога не запускает IO-изменение.

Удаление сначала освобождает текущие операции/Fragment/Publication, затем адресно переименовывает UUID-каталог в скрытый tombstone, убирает его current-pointer и удаляет копию/индекс/reader.json, derived-кеш и аудиокеш этой книги. Другие UUID не объединяются и не удаляются. При ошибке очистки остаточных файлов выдаётся сообщение. SAF-оригинал не затрагивается. Старый P0 аудиокеш был общим (до12 MP3); при подтверждённом удалении также очищается этот устаревший временный кеш, без удаления данных других книг.

Проверена дополнительная ветка AtomicFile: `reader.json.bak` и `current.json.bak` учитываются даже при отсутствии основного файла. Это предотвращает создание пустого NoteStore поверх существующей резервной записи.

## Оболочка чтения

Стабильный EpubNavigatorFragment/движок сохранён, SDK/зависимости не обновлялись. ReaderShell — Views-оболочка с верхней панелью «Книги / заголовок / Меню» и нижней панелью общего ползунка/процента/возврата. Центральное касание скрывает или показывает обе панели. Это действительно меняет высоту viewport: перед изменением сохраняется подтверждённый source-local якорь, затем ожидаются шрифт/положительная устойчивая геометрия и ACK. Pixel-scroll не используется как адрес текста. Нет прежних постоянно занятых строк диагностических и TTS-кнопок; команды перенесены в меню.

Центральный tap и движение яркости сохраняют уже подтверждённую точку внутри строки: контакт с интерфейсом больше не сбрасывает её к первому символу видимой строки перед reflow. Сохранение разрешено лишь при прежнем scrollY и видимом символе; обычная прокрутка/выделение не удерживаются на старой точке. Browser-регрессия начинает с CP233 внутри строки, отправляет настоящую последовательность DOM touch-событий центрального касания и шесть раз меняет высоту — во всех случаях CP233. Это моделируемые события, не аппаратный Android touch.

Меню: книги, оглавление, действующие пометки/комментарии, предыдущее место, настройки, озвучка пяти фраз и диагностика. Экспорт не объявлен готовым: он остаётся P3. Полные цветовые/пересекающиеся пометки, контекст и редактор — P2; действующие P0 пометки и добавление комментария сохранены. К выделению добавлена команда копирования цитаты. Отдельного интерфейса сносок нет; обычные ссылки и явный возврат действуют через прежний Readium.

Настройки: дневная/ночная/системная тема; три встроенные системные семьи с кириллицей (serif/sans-serif/monospace); размер70–280% с прежней шкалой Readium; яркость только окна. Шрифты не скачиваются, импорт пользовательских файлов не добавлялся. Тема/семья/яркость/видимость панелей сохраняются; прежний размер каждого reader.json остаётся. uiMode обрабатывается без пересоздания текущей Publication; авто следует системной теме. Изменения оформления при открытом редакторе не отменяют его IME-операцию восстановления. Обычные повороты по-прежнему пересоздают Activity с восстановлением по сохранённому якорю.

Кнопки и текст оболочки имеют явные цвета дневной/ночной темы, иконки системных панелей выбираются после создания decor window. Эта последовательность проверена запуском Activity в Robolectric; ранний вызов InsetsController был выявлен и исправлен до выдачи APK. Экран удерживается включённым при чтении, не на полке и не после Home.

## Жесты, навигация и возврат

Единый section-navigation.js сохраняет P0.8 края. P1-взаимодействия включаются для нового интерфейса; старые instrumentation-проверки движка могут использовать закрытый debug-хост с прежними кнопками. Это **изоляция тестового стенда**, не отделение пользовательских книг: production всегда использует прежний files/books-v1.

Приоритет: активное выделение и элементы/ссылки/пометки → левая полоса яркости → прокрутка/край. Полоса —10% ширины WebView. С первого движения в ней стандартный scroll предотвращается, яркость начинает меняться после12 CSS px. Долгий тап и маркеры выделения не перехватываются. Значение ограничено5–100%, системная яркость не записывается. На краю такой жест не создаёт переход. После touchcancel/нескольких пальцев отсутствует второй отложенный переход.

Короткое касание (<350ms, движение<8 CSS px) по боковым третям перемещает примерно на viewport минус одна строка; в центре меняет панели. Обычный краевой переход остаётся отдельным новым жестом48 CSS px, с проверкой края в начале и инерции. Ссылки/пометки не становятся командами зон. Текст/цитаты/процент не получают символов от хвоста или интерфейса.

Общий ползунок отображает весь канонический текст, не scrollY/scrollHeight. Используются source prefixes и code points, конец100% адресует последний читаемый символ. Изменения объединяются с задержкой140ms: предыдущая незавершённая навигация отменяется, остаётся последнее положение, без очереди всех промежуточных ресурсов. Программные обновления ползунка не запускают переход. Ресурсы без текста сохраняют прежнее visual position отдельно и не увеличивают процент.

До TOC/ползунка/пометки сохраняется одно предыдущее подтверждённое место (также для обычной ссылки). «Вернуться» восстанавливает его через тот же ReaderSession и ACK, включая visual position. Это одна точка на книгу, не полная история. Поздний callback не очищает history другой книги. Отказ проверки старой точки переводит сессию в RECOVERING, не объявляет неверный якорь успешным.

## TTS и совместимость

Обычный Edge маршрут, голоса, SSML и три отменяемые попытки сохранены. Команда остаётся ограниченной **пятью фразами**. Автоматическое открытие следующего документа сохраняет очередь; ручная навигация сбрасывает, пауза оставляет ручное продолжение. Home/блокировка не включают звук после возврата. Открытие меню/полки и изменение вёрстки ставят озвучку на паузу, не запускают автоматически.

Для адресного удаления добавлено владение кешем `cache/tts-p1/<UUID>` с прежними ключами текст/голос и пределом12 файлов на книгу. Переключение отменяет старые запросы перед привязкой нового каталога. Сетевой протокол и retry policy не менялись. Полная очередь/управление фразами и сохранение аудиосессии через пересоздание Activity остаются P4: после пересоздания доступен новый запуск пяти фраз, точное продолжение старой очереди не обещается.

Стабильный тест выявил гонку диагностического late WebSocket close: callback мог принести старый stage=playback уже после completed. Исправлена только обработка метаданных закрытия — она больше не откатывает playback/outcome. Добавлена отрицательная регрессия. Это не изменение сетевого маршрута/голоса и не заявление о новом Microsoft runtime PASS.

Source EPUB байтово не мигрируют, UUID и schema1 notes/reader/model остаются. Добавляются необязательные metadata/progress/previousPlace и настройки оболочки; старые пометки/черновики не изолируются, не очищаются автоматически и не требуют переимпорта. Логические главы P2 не становятся ресурсами из-за нового экрана. Диагностика не содержит романа, комментариев, URI/локальных путей или SSML; SAF URI хранится только в локальной настройке источника.
