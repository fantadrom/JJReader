## Пометки и совместимость

При первом доступе к прежнему reader.json NoteStore дополняет старые записи `noteVersion=2` и явным `color=yellow`, сохраняя прежнее жёлтое отображение. Сохраняются **все исходные поля**, в частности ID, цитата, комментарий, глава-ресурс/диапазон, hash и locator. Черновик тоже сохраняется. У документа остаётся schema1; EPUB/UUID/книжные каталоги и позиция/размер/настройки не мигрируют. Запись атомарна, не требует переимпорта и не изолирует «пробные данные».

Внутри текущего ресурса доступны «Пометка», «Цвет», копирование выделенной цитаты. Цвет можно сохранить без текста одним выбором; комментарий — с цитатой, курсором и клавиатурой, одним Save. Палитра фиксированная, подписанная: красный/синий/зелёный/жёлтый/фиолетовый. Можно добавить текст к цвету, менять/снимать цвет, сохраняя комментарий. Пустая запись без текста и цвета не сохраняется. Нажатие на выделение/значок даёт просмотр, редактирование и удаление; при пересечении диапазонов — выбор всех затронутых записей. Значок добавляется только для непустого комментария, чистый цвет не получает ложного значка.

Цветовые слои имеют детерминированный z-index по `(ресурс,start,end,id)` и максимальную суммарную прозрачность0.38. При наложениях прозрачность каждой записи делится на максимальную глубину перекрытия её диапазона; текст не выцветает даже при пяти наложениях. Дневной multiply/ночной screen сохраняют контраст букв; ночной Readium CSS не сбрасывает фон выделения. Больший слой рисуется выше при пересечении. Порядок добавления DOM-декораций не меняет изображение. Без цвета остаётся нейтральное подчёркивание и значок комментария; озвучка сохраняет отдельное синее подчёркивание. Пометки не объединяются в хранилище. Для некорректной привязки запись сохраняется и показывается отдельно с предупреждением, без придуманного перехода.

Черновик записывается сразу на изменение текста/цвета, не на debounce; явный Save повторно фиксирует текущее содержимое и заменяет запись с тем же ID вместо дублирования. При ошибке сохранения диалог не считается успешно сохранённым. Back оставляет черновик, явная «Отменить» удаляет его. Есть «Продолжить черновик» в списке; повторное редактирование того же ID продолжает черновик, а не перезаписывает его старой версией. При другом черновике требуется явный выбор продолжить его или заменить. Удаление одной записи даёт один уровень отмены, доступный в списке, в том числе после перезапуска; следующее удаление заменяет этот уровень, массовая очистка с подтверждением удаляет и черновик/undo. Это не многошаговая история.

## Логическая глава, источник и стоимость

`BookText`, `ChapterMap`, `BookAnalysis` образуют общий источник для P2 и P3. Source-local CP/локаторы P0 остаются неизменными. В отдельном report-корпусе ресурсы соединены двумя LF, с отображением `(ресурс,CP) ↔ общий CP` и таблицей UTF16-границ. Эти разделители не попадают в книгу, цитаты или процент чтения. Длины, hash, абзацные и словесные границы считаются один раз; проверка каждой пометки использует готовые смещения, а не повторный проход романа.

Цели TOC разрешаются по href/fragment и каноническим позициям исходных DOM-id тем же TextModel v1. **Глава может занимать несколько ресурсов, а один ресурс — содержать несколько глав.** Совпадающие parent/child цели берут более глубокое реальное название; отсутствующие/дублированные id, конфликтующие названия в одной точке и неоднозначная иерархия разных целей дают явную ресурсную границу. Уровень «часть/глава/подраздел» по имени файла не угадывается. Наследование известной главы прекращается на неоднозначном участке до следующего однозначного начала. Плоское TOC либо совпадающие родительские контейнеры не обрезают главу по очередному XHTML.

Карта сохраняется в `books-v1/<UUID>/analysis-v1.json` (algorithm `toc-cp-v1`) с hash исходных текстов, границами и реальными названиями. Извлечённый текст уже находится отдельно от EPUB в book.json. На полке «Действия → Пометки и контексты» читает их через `BookStore.snapshot`: потеря/повреждение EPUB не уничтожает замечания и доступный контекст будущего P3. При доступном источнике карта строится и для другой книги с полки; если EPUB утрачен до построения карты, остаётся честная ресурсная граница и сохранённые цитаты/комментарии. Удаление внутренней книги пользователем очищает эти файлы вместе с остальными данными.

## Контекст и группировка — общая основа P3

`ReportBuilder` получает BookAnalysis, снимок сохранённых пометок и N текущей книги (default350). Он возвращает `NoteReport / ReportGroup / ContextSpan / NumberedNote`, исходные интервалы, цвет/комментарий/цитату, названия глав и список неподтверждённых записей. P2-представление «Контексты» уже потребляет эту модель. P3 должен использовать её же для копирования и DOCX, без второго алгоритма контекста. Экспорт/окончательное копирование отчёта здесь не реализованы.

Контекст ограничен логической главой. Само выделение входит целиком вне бюджета N. Слева выбирается самое дальнее начало абзаца внутри N, справа — самое дальнее окончание. Если его нет, используются границы целых слов внутри бюджета (BreakIterator/Unicode CP); если цельного слова нет — контекст не разрезает длинное слово ради заполнения N. На обрезанных сторонах модель хранит признак многоточия, у действительного края главы его нет. Для редкой записи, чьё выделение само пересекает границу логических глав внутри XHTML, цитата сохранена полностью, внешний контекст не добавляется и такая запись остаётся отдельной группой. Она не пропадает и не соединяет главы.

Формализация объединения: для двух групп одной главы положительное пересечение выделения любой пометки с контекстом другой группы создаёт связь. Связные компоненты объединяются одновременно, контекст пересчитывается от min(start)/max(end) с тем же N; процесс повторяется до устойчивости. Простого пересечения двух участков контекста без выделения недостаточно. Интервалы полуоткрытые, касание концов не является пересечением. Сортировка `(start,end,id)` и компоненты исключают зависимость от порядка обхода/создания. Все исходные записи остаются отдельными; каждая входит ровно в одну группу, номера внутри группы связаны с диапазонами и подписями. Совпадения и пересечения не удаляются.

Список показывает логическую главу, цитату, цвет/комментарий, переход, редактирование и удаление; отдельный режим показывает нумерованные контексты. Есть возврат «К пометкам». Изменение N применяется ко всем сохранённым записям без их пересоздания и хранится отдельно для каждой книги. Список/его клавиатура N и редактор замораживают запись позиции на время IME и восстанавливают прежний якорь через revision/ACK; позднее закрытие списка не отменяет новый переход.

## Мелькание: установленное окно и новое условие показа

По коду прежняя последовательность была `nav.go()` → видимый WebView с началом ресурса → установка target scroll/ACK. Сохранённый semantic locator сам по себе не скрывал промежуточную раскладку. Это окно между фактическим вызовом навигации и подтверждением/рисованием целевой позиции; CSS-причина первоначального отступа не объявляется известной для EPUB пользователя.

`ReaderStage` добавляет **непрозрачный sibling-слой**, сохраняя работающий, видимый для движка WebView и его прежнюю геометрию. `ReaderRevealGate.begin` включает его **до фактического nav.go/loadUrl**; покрытие не зависит от того, успел ли новый JS уже загрузиться. После стабильного ACK и надёжной записи цели вызывается `WebView.postVisualStateCallback` для видимого WebView нужного href, затем ожидается pre-draw. Только тогда слой снимается. Фиксированного таймера показа нет:6s — timeout отказа с закрытым слоем и доступным меню, а не задержка раскрытия. Семантика RESOURCE_START/END_PAGE/END_TOP и произвольных якорей не меняется.

Перед раскрытием проверяются session, revision, documentId и serial запроса. Отмена/другой переход не позволяют старому callback снять новое покрытие. Проверенный видимый fallback после отмены может раскрыться как новый подтверждённый ресурс, с прежней диагностикой отказа исходного перехода. На время покрытия исключён старт TTS/меню навигации; при отказе меню доступно для повторного выбора. В диагностике добавлены PRESENT_HIDE, PRESENT_VISUAL_READY, PRESENT_REVEAL, а ACK остался прежним. GO-request может логироваться до PRESENT_HIDE; сам вызов native-навигации выполняется после него. Никакого текста книги/комментариев в эти события не добавлено.

**Точный физический кадр на Honor в этой среде не измерен.** Unit/Robolectric проверяют производственный gate с управляемыми сигналами visual/pre-draw, timeout, отменой и восстановлением, а ReaderSession — вызов presentation только после ACK/commit. Native ReaderP2Test дополнительно записывает первый непокрытый OnDraw, проверяет положительный native scrollY предыдущего длинного ресурса, порядок HIDE < ACK < VISUAL < REVEAL и итоговый CSS-gap. Этот тест собран, но runtime NOT_RUN; он не выдаётся за пройденное аппаратное измерение.
